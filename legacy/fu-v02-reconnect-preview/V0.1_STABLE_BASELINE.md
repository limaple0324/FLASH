# 輔V0.1 穩定基準

版本：V.01 / v0.1

這份文件是目前輔V0.1的穩定基準。之後任何改動都必須先列在變更清單中，沒有列入變更清單的功能與模組 API 不得修改。

## 變更規則

1. 未列入當次變更清單的功能，不修改。
2. 穩定模組之間不互相改程式碼，除非使用者明確要求。
3. 優先保留目前已驗證穩定的行為，不用高風險方式重構。
4. 需要新增功能時，先接在對應模組 API 邊界外，確認穩定後再納入正式基準。
5. 每次打包前要執行語法檢查，並清理 `.packaging`、`__pycache__` 等暫存。

## v0.1 禁止事項

以下項目除非使用者明確提出並要求更改，否則不得調整：

1. 禁止大搬動主程式結構。
2. 禁止把 30 萬字元單檔直接拆多檔。
3. 禁止重寫組別管理。
4. 禁止重寫主窗口判定。
5. 禁止重寫系統匣邏輯。
6. 禁止重寫 DPI / 雙螢幕邏輯。
7. 禁止改變快捷鍵重複清空規則。
8. 禁止改變 X 收回系統列行為。

## v0.1 穩定模組 API

以下 API 是目前單檔主程式內的「邏輯 API 邊界」，不是拆檔、不是重寫架構。之後除非使用者明確列入變更清單，否則不得修改對應 API 的既有行為。

### 1. GroupAPI

負責：組別新增、刪除、改名、排序、取得目前組別。

穩定規則：

- 保留多同步組管理。
- 保留組別順序記憶。
- 不重寫組別管理流程。

### 2. LaunchAPI

負責：啟動本組、整理本組、恢復位置、補開缺少視窗。

穩定規則：

- 整理本組才負責開啟、還原、移動已記錄的 Flash 視窗。
- 開啟同步不應任意重排視窗。
- 關閉遊戲後，同步窗口列表仍保留記錄，顯示為未開啟狀態。
- 已被其他組擁有的視窗，不可只靠位置相近被本組配對；跨組共用需靠啟動檔身份或本組已明確加入。
- 整理/同步前配對時，啟動檔身份優先，位置只作為備援。

### 3. MainWindowAPI

負責：設定主窗、上鎖、解鎖、取得主窗。

穩定規則：

- 每組主窗口獨立固定。
- 主窗口上鎖時，不可被同步窗口或其他組別隨機替換。
- 主窗口未上鎖時，才允許重新點選主窗口。
- 不重寫主窗口判定。

### 4. SyncAPI

負責：開始同步、停止同步、同步狀態、快捷鍵觸發。

穩定規則：

- 每組可獨立開啟或停止同步。
- 開啟同步只同步目前已綁定的視窗。
- 支援同步左鍵、同步鍵盤、同步滑鼠滾輪。

### 5. HotkeyAPI

負責：快捷鍵設定、清除、重複衝突處理。

穩定規則：

- 每組可設定同步啟停快捷鍵。
- 快捷鍵可清空成空白。
- 同步啟停鍵與整理本組鍵共用唯一鍵規則。
- 任一同步啟停鍵或整理本組鍵設定到同一顆按鍵時，以最後設定者為主，舊設定自動清空。
- 不改變快捷鍵重複清空規則。

### 6. CharacterAPI

負責：讀取角色ID、校正角色ID、檔名備援、跨組身份。

穩定規則：

- 角色 ID 讀不到時，以啟動檔名備援顯示。
- 同一個 Flash 視窗可依使用者設定，在不同組別中扮演不同角色。
- 角色身份不得寫入錯誤同步組。

### 7. MonitorAPI

負責：斷線偵測、掃描狀態。

穩定規則：

- 斷線偵測可選擇啟用或關閉。
- 偵測時是否允許打開縮小視窗，可由選項控制。
- 偵測結果顯示在程式內，不彈出干擾操作的小視窗。
- 偵測到的視窗或檔名會常駐顯示，不因掃描進度跳轉而消失。
- 斷線偵測目前只提示，不自動停止同步、不整理本組、不重開視窗。

### 8. TrayAPI

負責：系統匣、喚醒、關閉、X收回。

穩定規則：

- 主視窗按 X 收回系統匣，不直接關閉。
- 系統匣左鍵、雙擊、右鍵「顯示輔V0.1」都負責喚醒主視窗。
- 系統匣右鍵提供「顯示輔V0.1」與「關閉輔V0.1」。
- 不重寫系統匣邏輯。
- 不改變 X 收回系統列行為。

### 9. StatusWindowAPI

負責：小狀態窗、多組顯示、置頂、拖曳。

穩定規則：

- 小狀態窗置頂顯示。
- 可用任意位置拖曳。
- 多組同步時逐組顯示：組別、同步狀態、快捷鍵。

### 10. SettingsAPI

負責：AppData設定、outputs備份、machine id。

穩定規則：

- 設定保存於 AppData。
- outputs 保留同步設定備份。
- machine id 保護，避免換電腦誤套用舊設定。
- 不更改既有設定格式，除非有明確遷移方案。

## v0.1 允許變更紀錄

### 2026-07-05：LaunchAPI 跨組視窗配對收斂

使用者發現已設定在魔心次元組的 Flash 視窗被其他組別誤判。本次只調整 LaunchAPI 的配對優先順序與跨組位置配對規則。

變更範圍：

- 整理本組、同步前綁定視窗時，先用啟動檔身份配對，再用位置作為備援。
- 已被其他組擁有的視窗，不再允許只因位置相近就被本組配對。
- 跨組共用仍保留啟動檔身份配對，避免破壞已驗證的 A/B/C 共用視窗操作。
- 主窗口跨組判定規則不改，仍保留每組主窗口固定與上鎖邏輯。

禁止牽動：

- 不改 GroupAPI。
- 不改 MainWindowAPI。
- 不改 SyncAPI。
- 不改 HotkeyAPI。
- 不改 CharacterAPI 的角色 ID 讀取與校正。
- 不改 MonitorAPI。
- 不改 TrayAPI。
- 不改 StatusWindowAPI。
- 不改 DPI / 雙螢幕邏輯。
- 不改 X 收回系統列行為。

### 2026-07-05：HotkeyAPI 同步鍵與整理鍵衝突清除

使用者發現同步啟停鍵與整理本組鍵可同時設定成同一顆按鍵，造成按下快捷鍵時優先觸發整理本組，甚至整理到非目前預期的組別。本次只調整 HotkeyAPI 的衝突處理。

變更範圍：

- 同步啟停鍵與整理本組鍵納入同一套唯一鍵規則。
- 設定同步啟停鍵時，會清掉其他同鍵的同步啟停鍵與整理本組鍵。
- 設定整理本組鍵時，會清掉其他同鍵的同步啟停鍵與整理本組鍵。
- 啟動時若舊設定檔已存在同步鍵/整理鍵衝突，保守保留同步啟停鍵，清掉同鍵整理本組鍵。
- 不改快捷鍵輪詢順序，不重寫快捷鍵觸發流程。

禁止牽動：

- 不改 GroupAPI。
- 不改 LaunchAPI。
- 不改 MainWindowAPI。
- 不改 SyncAPI。
- 不改 CharacterAPI。
- 不改 MonitorAPI。
- 不改 TrayAPI。
- 不改 StatusWindowAPI。
- 不改 DPI / 雙螢幕邏輯。
- 不改 X 收回系統列行為。

### 2026-07-05：MonitorAPI 斷線偵測常駐名單固化

使用者已驗證斷線偵測合理、穩定。本次只調整 MonitorAPI 的狀態顯示方式，讓偵測到斷線的檔案或視窗名稱常駐顯示。

變更範圍：

- 持續偵測中只要偵測到斷線，狀態列會保留檔名或視窗名，例如 `斷線偵測：偵測到 1 個｜100靈.lnk｜每 1000ms｜掃描 5/14`。
- 後續掃描其他視窗時，掃描進度可繼續更新，但已偵測到的名單不會被覆蓋。
- 重新開啟斷線偵測、切換偵測組別、或執行單次掃描時，名單會重新刷新。
- 單次掃描會刷新當次偵測結果，並清除舊冷卻記錄，避免剛偵測過又手動掃描時被冷卻機制擋住。

禁止牽動：

- 不改 GroupAPI。
- 不改 LaunchAPI。
- 不改 MainWindowAPI。
- 不改 SyncAPI。
- 不改 HotkeyAPI。
- 不改 CharacterAPI。
- 不改 TrayAPI。
- 不改 StatusWindowAPI。
- 不改 DPI / 雙螢幕邏輯。
- 不改 X 收回系統列行為。

### 2026-07-05：MonitorAPI 掃描結果顯示改善

使用者已允許本次調整 MonitorAPI 的提示文字與顯示方式，目標是讓單次掃描、持續偵測與卡畫面疑似結果更直覺。

變更範圍：

- 卡畫面疑似結果顯示視窗檔名，例如 `卡畫面偵測：疑似 1 個｜160帥.lnk`。
- 持續偵測狀態顯示實際間隔，例如 `每 5000ms`。
- 斷線最低間隔為 1000ms，卡畫面最低間隔為 5000ms。
- 掃描按鈕加上滑鼠提示文字，說明單次掃描與最低間隔。
- `立即掃描` 改名為 `單次掃描`。
- `打開並掃描一次` 改名為 `打開縮小並掃描`。
- 卡畫面偵測只提示疑似視窗，不自動停止同步、不整理本組、不重開視窗。

禁止牽動：

- 不改 A/B/C 跨組同步已驗證穩定邏輯。
- 不改 LaunchAPI。
- 不改 TrayAPI。
- 不改 DPI / 雙螢幕邏輯。
- 不改 HotkeyAPI 快捷鍵重複清空規則。
- 不改 X 收回系統列行為。

### 2026-07-05：MonitorAPI 掃描範圍限定目前組別

使用者已允許本次調整 MonitorAPI，目標是讓斷線偵測與卡畫面偵測只掃描目前同步器畫面選取的組別。

變更範圍：

- 斷線偵測只掃描目前組別的主窗口與同步窗口。
- 卡畫面偵測只掃描目前組別的主窗口與同步窗口。
- 掃描數量以目前組別為準，例如 160 組 5 個視窗就顯示掃描 1/5、2/5。
- 斷線偵測處理後不再自動呼叫整理本組，避免掃描後擅自移動視窗位置。

禁止牽動：

- 不改 A/B 跨組同步已可用的判定邏輯。
- 不改 LaunchAPI 的整理本組流程。
- 不改 TrayAPI。
- 不改 DPI / 雙螢幕邏輯。
- 不改 HotkeyAPI 快捷鍵重複清空規則。
- 不改 X 收回系統列行為。

### 2026-07-05：MonitorAPI 自由開關與 Sync/Launch 邊界分離

使用者已允許本次調整 MonitorAPI、SyncAPI、StatusWindowAPI，目標是先處理 B 組同步窗口未跟隨，再處理偵測開關與同步/整理邊界。

變更範圍：

- 卡畫面偵測新增獨立開關，預設未啟用。
- 斷線偵測與卡畫面偵測分開控制，偵測功能需由使用者自行開啟。
- 同步快捷鍵不再因缺少視窗自動呼叫整理本組。
- 缺少視窗只在狀態/小狀態窗提示，補開與恢復位置仍屬於整理本組。
- 跨組共用的 B 組同步窗口可依啟動檔身份或記錄位置重新綁定，不因已被 A 組使用而被排除。
- 小狀態窗顯示每組視窗數、未偵測數與共用數。

禁止牽動：

- 不改 TrayAPI。
- 不改 DPI / 雙螢幕邏輯。
- 不改 HotkeyAPI 快捷鍵重複清空規則。
- 不改 X 收回系統列行為。
- 不拆檔、不重寫主程式結構。

### 2026-07-04：跨組同視窗角色判定
