更新日期：2026-07-25（台灣時間）

## 一、目前結論

SP1 已建立可測試的工程基礎，但**尚未完成**。

目前 `main` 與 `release/latest` 對應的仍是 **0.1.2 工程驗證版**。最新整合分支的
原始碼測試、來源自我檢查與 GitHub Actions Windows artifact 已通過；下載後的
包內驗證器、隔離 `--self-check` 與 Windows 11 基本 GUI 啟閉也已通過。但尚未
完成乾淨帳號、真正遊戲視窗、DPI／多螢幕、背景能力、斷線重連、安全輸入、
更新流程及正式發布驗收。

因此現階段只能稱為：

> SP1 工程基礎已實作並通過目前範圍的來源驗證；SP1 正式驗收尚未完成。

## 三、SP1 程式邊界

SP1 Engine 負責：

- 程式啟動、生命週期、持久化路徑、設定、紀錄、服務註冊與事件傳遞。
- 結構化自我檢查、損壞資料隔離、備份恢復與可追蹤錯誤。
- Recovery、Smart Reconnect、External Adapter 的固定契約。
- Windows 視窗識別、安全拒絕、操作區域重疊檢查及背景擷取能力探測。
- Windows 建置、自我檢查、成品雜湊、驗證包及單一「更新輔」入口。

SP1 不負責：

- SP2 的角色、活動、習慣、優先度與決策。
- SP3 的首頁、工作區、提醒卡及玩家呈現。
- SP3.5 的陪伴語氣、主動程度與信任表現。

遊戲特定識別與操作必須留在 Adapter 或 Plugin；未完成玩家批准、安全邊界及
Windows 實機驗證前，不得啟用真正遊戲輸入。`main.py` 只負責組裝與啟動，
不得成為跨層商業邏輯容器。

## 六、尚未完成

- 在乾淨 Windows 11 使用者帳號執行成品自我檢查、關閉重開與持久化驗證。
- 驗證單一「更新輔」能取得正確版本，且捷徑、圖示、工作列與無主控台視窗均正確。
- 設定並驗證真正 Adobe Flash Player 11 視窗身分。
- 驗證遊戲被部分遮擋、非前景及最小化時的實際畫面讀取能力。
- 以玩家明確批准的無害探測，驗證背景輸入安全性與不誤操作其他視窗。
- 實作並驗證真正斷線偵測、重新登入與失敗恢復流程。
- 驗證十四個視窗長時間運作、低處理器使用率、不造成遊戲延遲。
- 安全整合 `main` 與整合分支，完成當前版本的 GitHub Actions 與發布驗證。

目前通過的 Windows 證據只涵蓋 artifact 完整性、包內／隔離自我檢查及標題
「輔」主視窗的基本啟閉，並確認沒有殘留程序；不等於完整玩家、真正遊戲、
DPI／多螢幕、乾淨帳號、背景能力、更新流程或正式發布驗收。

## 七、SP1 驗收門檻

只有以下門檻全部通過，才能標示「SP1 完成」：

1. **來源門檻**：全部測試、原始碼編譯與完整來源自我檢查通過。
2. **Windows 成品門檻**：由欲發布 commit 建置 `FLASH.exe`，成品
   `--self-check`、版本資料、必要檔案與 SHA-256 全部通過。
3. **Windows 11 門檻**：乾淨帳號可啟動、關閉、重開並保留設定與紀錄；
   無多餘命令視窗，捷徑、圖示及工作列正確。
4. **真遊戲唯讀門檻**：正確辨識目標，不接受缺失、重複、最小化或無效範圍；
   完成遮擋、背景、最小化與多視窗驗證。
5. **安全恢復門檻**：真正斷線與重連流程通過；任何輸入均有玩家批准，
   不誤操作其他視窗，且玩家可隨時保持控制。
6. **發布門檻**：GitHub Actions 通過，`release/latest` 指向核准 commit，
   目標電腦的「更新輔」與下載成品驗證成功。
7. **文件門檻**：[`SP1_VERIFICATION.md`](../SP1_VERIFICATION.md) 的必要項目
   全部勾選，證據與 commit 可追溯。

在以上門檻完成前，正式狀態維持：

> **SP1 0.1.2 工程驗證階段；不是 SP1 正式完成版。**
