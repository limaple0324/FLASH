## 三、SP3 是累積層，不是另一套程式

SP3 必須累積承接 SP1 與 SP2：

- SP1 提供啟動、路徑、設定、紀錄、自我檢查、視窗安全與 Windows 能力邊界。
- SP2 提供角色、組別、活動、狀態、進度、提醒卡與工作區等可信資料。
- SP3 只負責把上層已決定的內容轉成玩家能看懂、少操作、不打擾的畫面。

固定資料流為：

1. SP1 偵測事實並提供安全能力。
2. SP2 更新角色、組別、活動、狀態並作出提醒／安靜決策。
3. SP3 取得唯讀 View State，呈現首頁、提醒卡、詳細資料與中文回饋。
4. UI 不自行猜測事實，也不直接修改領域狀態。

交付時不得：

- 複製出一套 `SP3` 專用原始碼。
- 讓 SP1、SP2、SP3 各自演變成互相漂移的工程。
- 建立只含 SP3、缺少 SP1／SP2 依賴的單獨執行檔。
- 把累積整合版誤標成「SP3 獨立 EXE」。

SP3 的「獨立交付檔案」是本層的狀態、證據與驗收文件；Windows 程式仍由同一套
累積原始碼建立。

## 四、已定案的 SP3 設計

### SP3-01｜產品呈現

首頁不是工程儀表板。玩家應能立即知道：

- 現在是哪一組、有哪些角色。
- 快捷鍵、啟動／停止與切換組別。
- 當前活動、進度、中斷狀態與下一步。
- 工作區與真正需要注意的提醒卡。
- 一句簡潔、當下有用的陪伴資訊。
- 首頁、活動、組別、功能、設定等次要入口。

### SP3-02｜陪伴體驗

呈現應隨農場、釣魚、副本、次元、守紀、神修等當前情境改變，只顯示現在真正
有用的資訊。當日限定活動只能在時間與事實成立時出現，不可猜測。

### SP3-03｜情感回饋

回饋的目的不是稱讚玩家，而是讓玩家感到被理解。固定原則是簡潔、時間準確、
有新資訊才出現、一次說清楚、不重複轟炸、不使用冰冷通知語氣，也不搶走玩家
注意力。

### SP3-04｜陪伴個性

「輔」的個性固定為可靠、守護、安靜、默契、信任。它不是討好型、命令型或
一直聊天型；玩家永遠保有最後決定權。

以上是設計定案，不代表四章內容都已完成程式接線。

## 五、目前已完成的程式

### 1. 玩家首頁第一版骨架

目前 `ui/home.py` 已提供玩家面向的 `HomeView`，並由 `main.py` 建立正常主視窗。
已具備：

- 以「輔」作為玩家看到的產品名稱。
- 顯示目前組別與角色摘要。
- 顯示目前狀態、工作區文字與提醒卡摘要。
- 提供「查看組別角色」與「查看目前狀態」入口。
- 首頁提醒卡可重新讀取唯讀快照並更新既有畫面。
- 正常 `main()` 已內建「基礎提醒卡（預覽）」候選，不依賴測試或外部注入；
  首次／未選保持停用，玩家可選擇、保存或關閉預覽。
- 玩家可調整並保存提醒卡顯示秒數，無效值會保留原設定並顯示中文錯誤。

目前首頁仍是第一版骨架，不是完整 SP3 首頁；但工作區已改由正常流程中的
`WorkspaceService` 提供唯讀快照，不再從視窗登記角色猜測目前狀態。

### 2. 提醒卡與 Windows 浮層骨架

目前已建立：

- 組別級提醒卡的玩家唯讀內容。
- 最多三張提醒卡限制。
- 一般安全預設 30 秒，並支援玩家自訂顯示時間。
- 首頁自動刷新與提醒卡到期清除。
- Windows 可用工作區讀取，以及工作列上方右下角堆疊定位。
- 可保留負座標的多螢幕定位計算。
- 置頂、無邊框浮動視窗的開啟、更新、關閉與清理。
- 可替換的卡片文字呈現器、樣式候選、選擇保存與關閉流程。
- 浮層啟動、停止、訂閱同步與主視窗關閉時的清理。
- 正常 `main()` 內建「基礎提醒卡（預覽）」工程候選；選擇、保存、重啟載入、
  清除、失敗回滾與主程式啟動隔離已有自動測試。

這些是可測試的呈現骨架。內建候選在首次啟動或尚未選擇時保持停用，不會自行
建立已啟用浮層；它只是工程預覽，尚不是正式最終視覺。真正遊戲事件也尚未產生
卡片，因此不能宣稱玩家正常啟動後已會收到正式提醒卡。

### 3. 組別角色清單與角色詳細資料

目前正常流程已可：

1. 從首頁開啟組別角色清單。
2. 依組別顯示玩家可見角色資料。
3. 點選角色並開啟單一角色詳細視窗。
4. 顯示組別、等級、分類、定位、備註、靈魂石與命魂。
5. 缺少資料時顯示「尚未設定」，不自行補造。
6. 使用內部穩定角色身分配對，但不向玩家顯示角色識別碼或視窗控制資料。

角色清單、詳細頁與關閉流程都有獨立視窗生命週期及失敗清理測試。

### 4. 靈魂石編輯入口與正常流程

角色詳細頁已正式提供「編輯靈魂石」入口，正常流程已接上：

- 以內部穩定角色身分綁定正確角色；同名、同欄位角色不會互相錯存。
- 開啟獨立編輯視窗並帶入目前紀錄。
- 支援新增、修改、清除與取消。
- 保存或清除成功後，重新取得正確角色資料並刷新仍開啟的詳細頁。
- 編輯器開啟時不切換到其他角色，避免未保存內容與角色畫面混淆。
- 保存／清除失敗時保留原紀錄與編輯視窗，顯示中文錯誤並寫入紀錄。
- 資料已保存但畫面刷新失敗時，明確告知「變更已保存」，不誤報原紀錄仍保留。
- 所有玩家訊息都不顯示內部角色識別碼、例外內容或私人磁碟路徑。

### 5. 命魂手動文字入口與既有流程（後續暫停）

既有手動文字工程流程中，角色詳細頁已提供「編輯命魂」入口：

- 玩家只看見命魂文字與「尚未設定」，不會看見穩定角色識別碼。
- 以安全角色選擇命令綁定正確角色；同名、同欄位角色不會互相錯存。
- 開啟獨立命魂編輯視窗並帶入目前紀錄，支援新增、修改、清除與取消。
- 保存／清除成功後重新取得正確角色資料並刷新詳細頁。
- 命魂與靈魂石編輯器雙向互斥；任一有未保存內容時都不切換角色或開啟另一資源。
- 保存／清除失敗時保留原紀錄與視窗，顯示中文錯誤並寫入紀錄。
- 資料已保存但畫面刷新失敗時，明確告知變更已保存。

以上只描述目前已存在的手動文字工程流程。使用者尚未定案命魂應如何處理及
讀取，因此本項不再延伸，也不能用來宣稱正式命魂產品能力已完成。

### 6. 目標視窗唯讀狀態呈現

正常啟動目前已有第一條不含遊戲輸入的真實唯讀事件鏈：

- SP1 真正執行目標視窗健康檢查，經 EventBus 與 SP2 執行期狀態提供給首頁。
- 首頁能分辨「尚未取得檢查結果」、「尚未設定」、「已就緒」與「目前不安全」。
- `main.py` 只交付玩家可見狀態；登記識別、handle、PID、視窗類別、位置、
  原始狀態代碼與例外細節會在進入 SP3 前移除。
- 執行期重新整理失敗時保留上一筆可信畫面，不把不完整資料覆蓋到首頁。
- 主視窗關閉後解除目標視窗、工作區與提醒卡訂閱，並停止到期監看。

此鏈只呈現目標視窗健康事實，不建立活動、進度、決策或提醒卡，也沒有送出
遊戲輸入。它不能替代真正活動、斷線與恢復事件的後續接線。

- SP3-01 至 SP3-04 的固定設計均有正式文件。

## 九、交付檔案與命名

### 倉庫內固定文件

本層固定主文件：

```text
docs/03_輔_SP3_產品呈現_狀態與驗收.md
```

它是 SP3 可辨識的獨立交付檔案，但仍須與 SP1、SP2 文件及整體彙整共同閱讀。

### 對外保存的可追溯文件

需要保存某次快照時，使用：

```text
輔_SP3_產品呈現_狀態與驗收_YYYY-MM-DD_<commit7>.md
輔_SP1-SP2-SP3_整體彙整_YYYY-MM-DD_<commit7>.md
```

其中 `<commit7>` 必須是建立文件與成品時的實際 Git 提交短碼，不可手填不存在
或不相符的提交。

### Windows 累積成品

SP3 不建立單獨 EXE。Windows 成品命名應表明它是同一套累積系統，例如：

```text
輔-整合工程驗證版-SP1-SP2-SP3-<version>-<commit7>-windows-x64.zip
輔_玩家測試版_<version>_<commit7>_windows-x64.zip
輔_<version>_windows-x64.zip
```

- 「整合工程驗證版」只能表示程式與封裝驗證，不代表 Windows 11 或玩家驗收。
- 「玩家測試版」只能在 Windows 11 基礎驗證完成後使用。
- 無狀態後綴的正式名稱只能在全部發布門檻完成後使用。
- 禁止使用 `輔_SP3.exe` 或建立 `SP3` 專用原始碼副本。
